  • ✕RAG 파이프라인이 무엇인지는 알지만 자사 문서로 돌려본 적 없음
  • ✕교육 수료증만 받고 끝 — 실제 역량 변화 측정 불가

Grepp Only

강의가 끝난 다음 날, "무엇이 바뀌었는지"를 숫자로 보고드립니다.

Grepp은 프로그래머스 코딩테스트로 국내 채용 시장의 개발자 역량을 평가해온 회사입니다. 그 인프라를 그대로 교육에 붙였습니다.

교육 전·중·후 3시점에서 수강생 역량을 정량으로 측정합니다. HRD 담당자와 임원은 이 리포트를 예산 집행 ROI 근거로 그대로 사용할 수 있습니다.

01

Pre-Eval · 사전 진단

입과 전 Python·LLM API·에이전트 설계 기초 역량 측정. 수강생 수준 격차 파악 후 강의 운영 조정.

→ HRD 진단 리포트 1
02

Train · 교육 중 실습 코드 평가

모든 실습 코드는 그렙 인프라 위에서 자동 채점·코드리뷰. 수강생별 코드 품질 추적.

→ 실시간 대시보드
03

Post-Eval · 사후 진단 + 리포트

수료 7일 후 동일 항목 재측정. 수강생별 정량 변화 + 적용 가능 영역 추천 리포트.

→ 임원 보고용 ROI 리포트
Curriculum · 2 Days / 16 Hours

매 세션 끝에 결과물이 손에 남는 구조

강의 중심이 아닌 "산출물 중심" 부트캠프. 각 모듈은 종료 시점에 GitHub에 푸시할 수 있는 작동하는 코드를 남깁니다.

Day 1 — 에이전트 기초부터 단일 에이전트 구축까지

// 09:30 — 18:30 · 점심 1h 포함
1h
M0 · Intro
에이전트 시장 동향, 엔터프라이즈 도입 사례 분석. 자사 적용 가능 영역 식별.
2h
M1 · 에이전트 해부
LLM, Tool Use, Function Calling, MCP의 작동 원리. 단순 챗봇과 에이전트의 본질적 차이.
결과물 · 개념 정리 노트
2h
M2 · 첫 에이전트 만들기
Claude API + MCP 도구 호출 에이전트. Python 100라인 안에서 작동하는 에이전트 1개를 직접 구축.
결과물 · 도구 호출 에이전트 (GitHub 푸시)
2h
M3 · RAG 통합
사내 문서 임베딩, Vector DB, 검색 품질 평가. 케이스: 사내 규정 문서 또는 고객 응대 매뉴얼.

1h
Wrap · Day 1 회고 + Day 2 프로젝트 주제 선정
팀별 프로젝트 주제 확정. 자사 시나리오 적용 가능성 검토.
결과물 · 팀 프로젝트 기획서

Day 2 — 멀티 에이전트와 프로덕션화
